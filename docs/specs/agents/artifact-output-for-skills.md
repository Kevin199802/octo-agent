# 产物落盘 — skill 作者须知

- **面向**：写 skill（SKILL.md）和随 skill 分发脚本的人
- **一句话**：**skill 不决定产物落在哪，宿主决定。** skill 只写相对路径、需要收纳就建相对子目录，其余交给宿主。
- **相关**：[`question` 工具 — skill 作者须知](question-tool-for-skills.md)（同类对外文档）、[SPEC-INS-028](../infra/insight-workdir-declaration.md)（宿主侧机制）

> 这份契约此前不存在，现有 skill 里的写法不算违规。本文档是把口头约定固化下来，供后续修改对照。

---

## 0. 为什么有这份文档

宿主（Octo Insight）把每个会话的产物收在一个**会话专属目录**里，文件管理面板只展示这个目录。产物没落进去，用户在界面上就看不到——文件其实写成功了，只是落在了别处。

宿主保证的事：**skill 里的相对路径，一定解析到当前会话的产物目录。** 你不需要知道它的绝对位置，也不该知道。

所以 skill 里任何形如「落到 X 目录」的句子，都是在替宿主做决策，而宿主的目录在不同会话、不同宿主下都不一样。

---

## 1. 三条规则

### 规则 1：不点名任何目录

「当前工作目录」也算点名——它是一个**具体位置的名字**，不是「随便哪儿」的意思。模型读到它会去拼出一个绝对路径，然后落到宿主没预期的地方。

```diff
- 产物写到用户当前工作目录，除非用户指定其他位置。
- 落地位置：当前工作目录，不另建子目录。
+ 产物用相对路径写，文件名取自源文件主名。用户明确指定了保存位置时按用户给的路径写。
```

### 规则 2：要收纳就建相对子目录，直接建

需要把中间产物、过程稿、素材归拢时，**在相对路径上建子目录即可**，不需要先问、不需要绝对路径、不需要自己定一个「输出根目录」。

```diff
- 在用户项目目录下建立：
-   用户画像报告输出/<项目名>-<时间戳>/
-     ├── 过程稿/
-     └── 交付件/
+ 建立本次运行的目录（相对路径）：
+   <项目名>-<时间戳>/
+     ├── 过程稿/
+     └── 交付件/
```

两处变化：去掉「在用户项目目录下」（规则 1），去掉自造的 `用户画像报告输出/` 这一层——**给产物分类是宿主的事**，skill 再套一层只会让用户多点一次。

子目录在文件管理里是可以点进去的正常文件夹，中间产物放进去不会丢，也不会污染交付区。

### 规则 3：脚本用相对路径，默认值就是 `.`

随 skill 分发的脚本同理。带 `--workdir` / `--base-dir` 这类参数时，**默认值写 `.`**，让它落在宿主给的当前目录里；不要在脚本里硬编码目录名，也不要 `Path.home()` / `os.getcwd()` 之后再拼绝对路径。

```python
# 好
parser.add_argument("--base-dir", default=".")
run_dir = Path(args.base_dir) / f"{project_name}-{timestamp}"

# 不好：自造输出根 + 绝对化
run_dir = Path(args.base_dir).resolve() / "用户画像报告输出" / f"{project_name}-{timestamp}"
```

## 2. 一个容易漏的坑：写到源文件旁边

把产物写在**输入文件同级目录**，是这份契约唯一救不了的写法：

```python
# extract_transcript.py 现在的写法
out_path = os.path.splitext(input_path)[0] + ".transcript.txt"
```

用户上传的材料在宿主的**上传区**（跟产物区是两个目录）。跟着输入路径走，中间产物就落进了上传区，用户会看到自己的材料堆里冒出一堆没上传过的文件。

改法：产物一律相对当前目录，不跟随输入路径。

```python
out_path = Path(os.path.basename(input_path)).with_suffix(".transcript.txt")
```

## 3. 自查清单

改完 SKILL.md 和脚本后过一遍：

- [ ] 全文搜「当前工作目录」「用户项目目录」「工作目录下」——应为 0 处
- [ ] 全文搜盘符（`C:\`、`D:\`）和 `/Users/`、`/home/`——应为 0 处
- [ ] 脚本里搜 `.resolve()`、`os.getcwd()`、`Path.home()`——确认没有用它们去决定**产物**落点（用来解析 skill 自带资源没问题）
- [ ] 脚本的目录类参数默认值是 `.`
- [ ] 没有自造的「输出总目录」层
- [ ] 产物路径不跟随输入文件路径
- [ ] 需要收纳的中间产物，有一个明确的相对子目录，且 skill 里说清了叫什么

---

## 4. 边界

- **用户明确指定位置时听用户的**——这条不变，且应当在 SKILL.md 里保留。宿主只接管「用户没说」的默认情况。
- **读取输入**用宿主给的路径（通常是绝对路径），不受本契约约束；本契约只管**写**。
- **skill 自带资源**（`scripts/`、`references/`、`templates/`）按宿主注入的 skill 基准目录解析，与产物落点无关。
