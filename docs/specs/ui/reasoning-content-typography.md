# SPEC-INS-010 聊天区排版产品化 — 现状取证 + 设计对接

> **上游已实现**:✓ 正文 `<Markdown>`、✓ 思维链 `reasoning-part`、✓ 思考指示器 / 单行摘要。
> 本 spec 只规划 Octo 定制（insight 作用域覆盖，**不动上游、不动全局 token**）。
> **本文档是给「我们自己」的现状取证 + 验收指南。** 给设计师的产出是 → ① 按 §3 截出的**现状截图**；② `docs/tokens.md`。

---

## 0. 目的与产出物

**痛点**:思维链与正文在平铺下无视觉边界，整体是「半魔改、低保真」感。

**关键认知**(本次校正):
- **设计师不看本文档的元素表**——光看表他不知道要做什么。设计师拿到的是 **截图 + `tokens.md`**。
- 本文档帮**我们**做两件事:① 把每个元素 / 状态**可靠复现并截图**；② 对未实现的功能（思维链折叠 / 容器 / 标签）先搭一版**粗 UI** 再截图。

**做**:正文排版规范、思维链与正文的视觉区分、思维链**折叠**。
**不做**(业界少见 + 上游无):思考时长、思考结束态。

## 2. 设计方向（简）

业界（ChatGPT / Claude / DeepSeek / Gemini）区分思维链的共识 = 「**标签 + 容器 + 弱化排版 + 折叠**」四件套；现状只有「弱化排版」一件套（13px / 灰），故平铺时分不清。

**本期补**:容器 + 标签 + 折叠。实现**优先纯 CSS**，全部挂在 `[data-component="reasoning-part"]` 上（`border-left` / `background` / `::before content` / 折叠交互），尽量不改上游 JSX。

> 容器形态、标签文案、折叠默认态由设计师定（见 §6）。

## 3. 现状取证（核心）— 如何可靠截图

> **为什么要专门取证**:真实对话里元素不会齐全（表格 / 引用 / 数学 / 嵌套列表很少同框），**思维链更不是每轮都触发**（依赖推理型模型）。随便聊几句截图无法覆盖。

### 3.1 首选工具:dev-only「排版样张页」（确定性）

在 insight 下（insight 自研代码）建一个**仅开发环境可见**的样张页，用**真实组件**渲染固定样张 → 任意时刻可截、无模型随机性，也是搭折叠粗 UI 的地方。

- **正文**:`<Markdown text={全元素样张} />`，渲染 §3.4 的样张。
- **思维链**:`<div data-component="reasoning-part"><Markdown text={含标题/列表/代码的样张} /></div>`，复刻真实结构。
- **未实现功能**（容器 / 标签 / 折叠 / 降级态）:在样张页里搭粗 UI 截图给设计师参考。

### 3.2 真实链路抽查（确认样张 = 真实）

| 对象 | 步骤 |
|---|---|
| 正文 | 任意模型，发 §3.4 样张让其原样输出，核对与样张页一致 |
| 思维链 | **切推理型模型**（DeepSeek-R1 / 带 thinking 的 Claude / o 系列）+ 多步推理问题（如「比较 A/B/C 方案并推导取舍」）；**摘要开关开/关各截一次** |
| **弱模型降级** | 切**不返回 reasoning** 的模型，发同一问题，确认**无任何思考 UI 残留**（见 §5） |

## 4. Token 工作流（设计师那条线）

- **真相来源**:`docs/tokens.md`（设计命名 `text.primary` 等，与代码 `theme.css` 的 `--text-strong` 是**两套**，中间有翻译层）。
- **流程**:设计师审 `tokens.md`（决定是否更新）→ 基于它设计聊天区，**优先复用全局 token** → 超出部分由设计师给**组件级 token** → 我们翻译进 **insight 作用域覆盖层**。
- **防血溅（强约束）**:不改全局 `theme.css`；新值落 `--octo-md-*` / `--octo-reasoning-*` 命名空间，**集中在一个文件**（建议 `packages/app/octoapp/pages/insight/conversation-typography.css`），每块注释「覆盖上游什么 + 为什么 + 设计出处」，确保一处可定位。

## 5. 降级方案（模型依赖）

思维链（及其容器 / 标签 / 折叠）**依赖模型返回 `reasoning` part**。弱模型不返回，则只有正文。

- **原则**:所有思维链装饰**纯挂在 `reasoning-part` 上**。无 `reasoning` part → 整组不渲染 → 弱模型**自动退化为「纯正文」**，不出现空容器、孤标签、空折叠。
- **天然成立**:纯 CSS 作用域方案下，元素不存在则样式不生效，无需额外 JS 分支。
- **验证**:§3.2 弱模型抽查必须确认无残留。
- **流式注意**:`reasoning` 先到、`text` 后到时容器的出现时机；reasoning 为空白会被 `trim` 过滤而不显示。
