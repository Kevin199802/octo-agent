# SPEC-INS-022 Insight 响应式布局适配（窄屏三栏 / 抽屉）

- **状态**：草案（v2 已实现，外网，UXAI 分支 `feat/insight-adaptation-v2` / PR #369；未真机验证，待设计确认）
- **领域**：ui/insight
- **上游已实现**：✗（insight 自建；上游 opencode 无等价三栏响应式）
- **关联**：[SPEC-INS-009 任务面板按需弹出](insight-result-panel-reveal.md)（面板 reveal/collapse 状态机的真相源，本 spec 只加"响应式收起"这一维）

> 面板**内部**（ResultViewer / FileManager 表格、预览区）的自适应由各模块自行维护，不在本 spec 范围。

---

## 背景 / 目标

Insight 是 侧栏 + 对话 + 右侧面板 三栏布局。窗口变窄时若不适配，会出现：
- 面板内容被压扁到不可读（列表/预览折叠）；
- 面板/侧栏一旦收起就没有唤回入口（功能不可用）。

目标：对齐 Claude 桌面端——窄屏时依次把右侧面板、左侧栏收进**抽屉**，但**始终可经按钮唤回**，且各区不被压到不可用宽度。

## 版本历史（新老规则以时间戳为界）

### v1 — 2026-07-18 初版（PR #369 原始实现）

> 前身 PR #342 曾用「面板 `min-width:800px` + 外层横向滚动」方案，被否（窄屏内容仍需横滚、体验差），#369 重建时已去掉。

- **右侧面板**：`matchMedia(max-width: 1580px)` 命中即收起；`panelVisible` 加 `!responsivePanelCollapsed` 条件。
- **左侧栏**：`matchMedia(max-width: 767px)` 命中即隐藏；汉堡按钮唤出 `absolute` 浮层侧栏 + **半透明遮罩** `rgba(0,0,0,0.3)`；空态也放汉堡；导航自动关。
- **唤回**：收起态的「产出 (N)」badge 被 `!responsivePanelCollapsed` 挡掉 → **右侧面板收起后无法唤回（失能）**。
- **全局窗口** `minWidth: 1024` 不变。

**v1 暴露的问题**（→ 触发 v2 重做）：
1. 固定 1580 断点与「聊天/面板最小宽」互相打架：1580 收起点在多数笔电（1366/1440/1512）之上，且 1580~1226 区间聊天会被压到 450 以下。
2. 收缩时被挤的是右侧面板（`flex:1`），内容被压扁。
3. 面板收起后无唤回入口（失能）。
4. 抽屉带遮罩、宽度 `min(720px,90vw)` 盖满对话区。

### v2 — 2026-07-18 重做（当前，commit `268a076fb` 起）

对齐 Claude，规则如下。

#### 关键常量
| 名称 | 值 | 位置 |
|---|---|---|
| `CHAT_MIN` | 450 | insight/index.tsx 顶部 |
| `PANEL_MIN` | 480 | insight/index.tsx 顶部 |
| 左侧栏收起断点 | 窗口 `< 745px` | 同段 `matchMedia` |
| 全局窗口 `minWidth` | 600（原 1024） | packages/desktop/src/main/windows.ts ⚠️ |
| 右侧抽屉宽 | 480（= `PANEL_MIN`） | 抽屉容器 |

#### 收缩优先级（先挤聊天，面板守 480）
- 聊天列宽 = `effectiveChatWidth` = 把用户拖拽偏好宽钳制到 **`[CHAT_MIN, 容器宽 − PANEL_MIN]`**。
- 即：窗口变窄先挤聊天列，右侧面板恒 `≥ 480` 不折叠；分隔线拖拽保留（拖的是偏好宽，受此钳制）。
- `容器宽`（对话↔面板容器 = 窗口 − 侧栏）由 `ResizeObserver` 实测，随侧栏拖拽自适应。

#### 动态收起（不用固定 media-query 数值）
- **右侧面板**：`容器宽 < CHAT_MIN + PANEL_MIN`（=930）时收起。默认侧栏（296）下约等于窗口 ~1225px。
- **左侧栏**：`窗口 < 745px`（≈ 侧栏296 + 聊天450）时收起。

> 断点为何不用 Claude 的 1050：我方侧栏 296 + 聊天最小 450 + 面板最小 480 = 1226，1050 与「不压到不可读」无法兼得。故改为**由最小宽推导的动态收起**，保证聊天恒 ≥450、面板恒 ≥480。数值可调。

#### 抽屉（对齐 Claude）
- **无可见遮罩**；改用一层**透明点击层**兜住抽屉外点击 → 点空白 / 切会话 / 再点按钮都关闭。
- **左右抽屉互斥**：开一个自动关另一个（`<745` 时左右都收起、可能同时被唤起，避免透明点击层跨容器叠加）。
- 右侧抽屉 `480` 宽贴右、盖在聊天右侧（左侧聊天仍可见）；左侧抽屉贴左、侧栏自然宽。
- **收起态打开产物自动唤抽屉**：收起时点对话内产物卡片 / 文件卡片 → 统一走 `revealPanel()` 自动弹出右侧抽屉（解决"点了没反应"的失能）。

#### 面板挂载（无过渡动画）
- 面板挂载 / 聊天列宽度**直接跟 `panelVisible`**，无开合过渡动画。
- 旧版 `panelMounted / panelExpanded / panelAnimating` + 双 rAF 动画状态机**已移除**：它与响应式 `containerWidth` 在"切模块→切回 / 快速改宽"时会竞态（漏取消的 rAF 把 `expanded` 拉回 true 却已卸载面板 → 右侧灰底）。鲁棒性优先去掉（Claude 无此动画，左侧栏隐藏本也无动画）。
- `ResizeObserver` 忽略 0 宽测量（切走时本页 `display:none` 会量到 0，保留最后已知宽，切回不闪）。

#### 面板开关（统一，一个按钮管所有宽度）
- 顶栏一个 `layout-right` 图标按钮（有会话即显示）：
  - 宽屏（容器 ≥930）= inline 收起/展开（`panelCollapsed`）；
  - 窄屏（容器 <930）= 开合右侧抽屉（`panelOverlayOpen`）。
- 图标 **实心** `layout-right-full` = 面板展开中，**描边** `layout-right` = 已收起。
- 移除 v1 的「产出 (N)」badge（概念收敛为这一个开关）。
- 侧栏收起态另有汉堡按钮（`menu` 图标）：顶栏 + 空态各一。

## 验证（外网可复现）

前置：本地起 Electron 应用，**改了 `windows.ts` 必须重启进程**（改主进程，热更新不生效）。

1. **收缩优先级**：宽屏进会话，缓慢拖窄窗口 → 应看到**聊天列先变窄，右侧面板宽度稳定不折叠**；继续拖到容器 <930 → 面板收起。
2. **右侧抽屉**：面板收起后，点顶栏 `layout-right` 图标 → 右侧滑出 480 宽抽屉、**无遮罩**、左侧聊天仍可见；点抽屉外空白 → 关闭；再点图标 → 关闭。
3. **收起态打开产物**：面板收起态下，点对话里的产物卡片 → **自动弹出右侧抽屉并显示该产物**。
4. **左侧栏抽屉**：拖窗口到 <745 → 侧栏收起，顶栏/空态出现汉堡；点汉堡 → 左侧滑出侧栏、无遮罩；点空白/点会话 → 关闭。
5. **互斥**：拖到 <745（左右都收起），先开右抽屉再开左抽屉 → 右抽屉应自动关闭（任意时刻最多一个）。
6. **图标态**：面板展开时图标实心、收起时描边。
7. **窗口下限**：窗口应能拖到 ~600px（验证 `minWidth` 生效，需已重启）。
