# agent 产物落点约束 与「路径出处」不可判定

> 面向:困惑于"我们为什么要用插件去改产物落盘路径、这是不是业界标配、能不能干脆在系统提示词里说清楚"的读者。

## 0. 一句话

**产物该落哪，是运行时的策略，不该进模型的上下文；模型只给文件名，运行时确定性地把它落到该去的地方。** 这就是业界标配（Code Interpreter 的 `/mnt/data`、各家沙箱根）。我们从"提示词里塞绝对路径"迁到"插件重定向"，方向完全正确。剩下的所有别扭，都来自一个**自找的错位**：我们要的默认落点（会话 outputs）比"工作目录"更窄，而整套标准机制（工具 schema、权限边界、模型心智）都是按"工作目录"对齐的。

---

## 1. 需求：产物必须进 outputs，否则文件管理读不到

insight 会话的磁盘布局（都在选中目录下的 `.octo/<sessionID>/` 里）：

```
<选中目录>/.octo/<sessionID>/
  ├─ uploads/    用户上传的原始材料
  ├─ outputs/    交付产物 —— 文件管理面板只读这里
  └─ tmp/        中间/临时文件
```

关键约束：**文件管理面板只展示 `outputs/`**。所以"模型生成一个交付文件"必须最终落到 `outputs/`，否则用户在界面上看不到它（文件其实写成功了，只是落在别处）。

注意 `outputs/` 是**工作目录的一个子目录**，不是工作目录本身——uploads/tmp 是它的兄弟。这个"比工作目录更窄"是后面所有麻烦的根。

---

## 2. 演进：从"提示词塞路径"到"插件重定向"

### 2.1 老做法（反模式）：把绝对路径注入对话

早期为了让产物进 outputs，客户端**每轮**往对话里注入一条 synthetic 指令，形如 `[输出目录] <绝对路径>`，指望模型据此写对地方。

后果见 [standing-instruction-echoed-by-weak-model.md](standing-instruction-echoed-by-weak-model.md)：弱模型分不清"背景配置"和"这轮要做的事"，连发个"你好"都会把这条绝对路径复述出来。**根因不是"系统提示词会被背出来"**——正常 system prompt 模型不会照抄；是因为这条路径被放成了**对话通道里的、每轮都在的"现在去做"指令**。

### 2.2 新做法（业界标配）：运行时确定性重定向

`octo-outputs-redirect.ts` 插件挂 `tool.execute.before`，对 insight 会话的落盘工具，把**相对文件名**就地改写成 `<...>/outputs/<文件名>`。模型只需给 `用户画像.md`，绝对路径**永不进模型上下文**。

为什么这是业界标配，而不是我们的土办法：

- **能力寻址 / 沙箱根不可被模型改**：沙箱根是运行时固定的、模型改不动的；模型给相对名，运行时解析。OpenAI Code Interpreter 一切读写都在 `/mnt/data`，模型从不拿绝对路径。
- **把"决定落点"从"不可靠的模型输出"挪到"确定性的运行时"**：路径不在 prompt 里，就没有 2.1 的泄漏，也不依赖模型记住一长串路径。

**把路径放进提示词才是反模式；用运行时约束路径是标准。** 你的迁移方向对了。

## 3. 为什么这事没那么简单：自找的"默认落点 ≠ 工作目录"错位

标准链路里，"默认落点"和"免弹窗的允许区"**是同一个东西 = 工作目录**（`instance.directory`）：

- 相对文件名 → 解析到工作目录；
- 写工作目录**外** → `assertExternalDirectory` 弹权限（见 [permission-ask-and-always-allow.md](permission-ask-and-always-allow.md)）；
- 写工作目录**内** → 静默放行。

我们把工作目录设成**选中目录**，却要默认落点是它的**子目录 outputs**。于是模型写到工作目录根 `D:\测试 insight\x.md` 时：

- `containsPath(target, 工作目录)` = true → **标准机制认为"在你家里"，静默放行、不弹窗**；
- 但它**不在 outputs** → 文件管理读不到。

我们为了把默认从"工作目录根"收窄到"outputs"，额外贴了插件去改相对路径。**这一层贴片，就是所有 bug 的来源** —— 因为它对绝对路径无能为力（见 §4）。

> 换句话说：业界不难，是因为业界**不做这种分离**（Code Interpreter 里 uploads 和 outputs 同在一个工作目录，面板展示这个目录里出现的文件）。我们的难，来自"outputs 要独立、面板只读 outputs"这个自定义分离。

## 4. 残留长尾：模型/skill 拼绝对路径，绕过重定向

插件设计上**只碰相对路径**（`path.isAbsolute` 直接放行，尊重"用户显式指定的位置"）。于是出现内网偶现的错位：

- 弱模型或第三方 skill 在用户**没**指定路径时，仍然把上下文里的 `Working directory: D:\测试 insight`（`session/system.ts` 注入）拼成 `D:\测试 insight\x.md` 去 write；
- 这是**绝对路径** → 插件按设计放行 → 落到选中目录根，绕过 outputs。

**取证方法**（值得记住的排查手法）：直接查 SQLite。`session.agent` 是 `octo_insight`（闸门没问题），而 `part` 表里 write 的 `state.input.filePath` 是 `D:\测试 insight\xxx.md`（绝对、指向根）——一眼定性为"模型给了绝对路径"，而非缓存/权限/时序问题。

为什么模型会这么干？三条指令打架：

1. 上游 `write` 工具 schema 的参数说明白纸黑字 `The absolute path to the file to write (must be absolute, not relative)`；
2. 系统上下文把 `Working directory` 喂给模型；
3. 我们的 insight 提示词说"只给文件名"。

强模型听 3，弱模型被 1+2 带走。第三方 skill 更直接——它自己的提示词写「落地位置：当前工作目录」，等于**替宿主做了落点决策**，忠实的模型照做就落到工作目录根。

## 5. 核心认知：路径"出处"无法从工具参数判定

很自然会想："那就区分'用户提示词里明文给的路径'和'模型自己编的路径'，前者遵从、后者收进 outputs。" **这条路走不通**，必须讲清为什么：

- 工具调用的参数里**不携带出处**。模型完全可以把用户的话改写、归一化后再塞进 `filePath`。拿原始提示词做子串匹配，会漏（用户说"测试目录下"、模型写成 `D:\测试\`），也会误判。
- **但"用户有没有明文给路径"这个判断本身是模型的活**——模型看得见用户消息。所以它**可以、也应该在系统提示词里表达清楚**（"没给就只写文件名，给了才按用户路径写"）。

这两句不矛盾，关键是分清**谁来判**：

| | 判断"用户给没给路径" | 机械地把相对名落到 outputs |
|---|---|---|
| 谁做 | **模型**（看得见 user 消息，prompt 说清即可） | **插件**（确定性） |
| 可靠性 | 指令一致时高；上限=指令遵从 | 确定性 |

所以"系统提示词能不能说清楚？"——**能**。之前显得"不可能"，是因为①在说另一件事：插件**事后**只拿一个 `filePath` 想反推出处，那才不可能；②当时指令自相矛盾（§4 的 1 vs 3）。**消除矛盾 + 一处清晰规则 + 确定性搬运机制**，就是能拿到的上限。

> 硬保证做不到：要同时"保留独立 outputs"+"honor 任意用户路径"+"不靠模型自觉"+"不改上游 write"+"不弹框刷屏"，在数学上不可兼得——因为"模型拼了 cwd"和"用户就想写工作目录根"字符串完全一样。想硬保证必须松一条约束。我们选择：**不硬保证，靠消除矛盾把长尾压到可忽略**。

## 6. 我们最终的落法（2026-07-30）

1. **提示词消矛盾**（真相源在宿主 agent）：insight 提示词把"只给文件名"强化为**明令禁止**带目录/盘符/路径分隔符/「当前工作目录」/绝对路径；仅当用户明确指定位置才按用户路径写。
2. **skill 保持位置无关**：skill 不该点名任何具体目录（"当前工作目录"就是元凶）；产物落点是**宿主**的策略，skill 只描述"输出一个文件名"。关注点分离。
3. **插件按"是否落盘产物"扩集合**：重定向闸门从"只 write"扩成"落盘产物工具集 `{write, edit}`"——判据是**以 `filePath` 落盘产物**，不是工具名；`apply_patch`（参数是整段 `patchText`、无单一 filePath）进不来，恰好和"它对 insight 仍 deny"自洽。
4. **不靠关工具兜落盘**：产物错位靠上面的提示词硬规则收敛，不靠关 bash（bash 因 skill 需要已放开，见 SPEC-INS-021）。

刻意**没做**的：把"工作目录内的绝对路径"强行收进 outputs——因为用户真说"写到 `D:\测试\`下"时那样是错的（§5 的 honor 用户路径）。

---

## 7. 判据速记

- 产物落点是**运行时策略**，不进模型上下文；模型只给文件名。
- 想约束落点，用**运行时/插件**（确定性）；别把路径写进 prompt（泄漏 + 不可靠）。
- 出处（用户给的还是模型编的）**无法从工具参数判定**；能判的是模型（看得见 user 消息），所以规则写进 prompt、由模型执行，插件只做机械搬运。
- 别把默认落点定得比工作目录窄，除非你接受要额外贴一层、并处理"绝对路径绕过"的长尾。
- skill/工具描述**不要替宿主指定落点**；"落地位置=当前工作目录"这类是反模式。
