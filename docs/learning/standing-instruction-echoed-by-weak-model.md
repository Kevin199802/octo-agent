# 常驻/条件性指令塞进 user turn → 弱模型当当前任务复述

> 锚点案例:insight「发个『你好』，内网模型就回一段带 outputs 绝对路径的话」（SPEC-INS-014 v5 / UXAI PR #368）。

## 现象

insight 会话每条用户消息后面，客户端都无条件追加一个 `synthetic` text part：

```
[输出目录] 生成/导出文档时,用 write 工具写入此目录:D:/…/insight/ses_xxx/outputs/
```

`synthetic` 部分气泡不渲染、但模型可见。用户只发「你好」时——没有附件、没有别的任务——上下文里唯一的祈使句就是这条 `[输出目录]`。内网弱模型抓住它，回复「好的，已记录！后续所有生成/导出的文档都会写入 D:/…/outputs/」，把内部绝对路径暴露给了用户。

## 本质

**把「常驻/条件性指令」塞进当前的 user turn，弱模型区分不了「背景配置」和「这轮要做的事」。**

- 强模型会把「需要时才用」的背景约定放一边；弱模型倾向抓最近一条祈使句照做或复述。
- 空问候/无实质任务时最危险——没有真实任务可锚定，模型就拿这条注入指令当锚点。
- 「每轮都注入」进一步放大命中概率（等于每轮都在提醒它）。

这类注入常常是**绕路的产物**:某个值是运行时才知道的（如本例 `outputsDir = projectDir + sessionId`，静态系统提示词里写不了绝对路径），于是有人把它塞进每轮消息去补。绕路留下的代价就是这个副作用。

## 怎么避免（优先级从高到低）

1. **釜底抽薪——用工具/系统兜底，别用提示词指挥**。本例:让 agent 的相对写入由服务端确定性解析到工作目录（`相对 filePath → 会话 outputs/`），模型只写文件名、根本不需要知道路径。指令彻底退出对话上下文 → 没有可复述的东西 → 问题从根上消失。这也符合「确定性优先、拒绝启发式」——别指望模型正确搬运路径。落点见 [octo-outputs-redirect.ts](../../packages/opencode/src/agent/octo-outputs-redirect.ts)。
2. **常驻配置放常驻位置**（系统提示词 / 会话级一次性上下文），不要混进每一轮的 user 内容。至少别「每轮注入」。
3. **别靠改措辞/换位置**去压制复述——弱模型照样会 latch，治标不治本。「只要它还在上下文里，弱模型就可能复述」，唯一稳妥的「不暴露」是「根本不放进对话」。

> 一句话判据:**你想让模型「知道但通常不提」的东西，不要作为 user turn 的指令喂进去**——弱模型做不到「知道但不提」。要么进系统层当背景，要么干脆用代码兜底、不进上下文。
