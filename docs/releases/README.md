# releases — 内网版本改动记录

内网仓库打包与外网(UXAI dev)之间没有自动同步渠道,版本内容只能人工传递。本目录是每个内网版本改动的真相源:一个版本一个文件(`<version>.md`),同时承载**开发版 Changelog**(给开发,含 commit)与**运营版 Release Notes**(给运营,面向用户措辞)。

当前只覆盖 **insight 线**;其他产品线(studio / design / make / chat)如需纳入,按节追加即可。

## 文件结构

每个版本文件头部维护三个指针:

| 指针 | 含义 |
|---|---|
| 基线 commit | 上一个内网版本对应的 UXAI commit,diff 起点 |
| 已梳理至 commit | 本文件内容覆盖到的 UXAI dev commit,增量更新的游标 |
| 定版 commit | 内网实际打包所取的 commit;打包前留空 |

## 维护流程

1. **起草新版本**:以上一版的「定版 commit」为基线,梳理 `基线..dev` 的 insight 相关提交,写入新文件,记录「已梳理至」。
2. **增量更新**(dev 又进了要塞进本版本的提交):对 Claude 说"更新 0.6.0 改动清单"即可——只 diff `已梳理至..origin/dev`,把新增条目**同时追加到开发版和运营版两节**,然后推进「已梳理至」指针。两节必须一次改完,不允许只更新一半。
3. **定版**:内网打包后,把实际打包的 commit 填入「定版 commit」,状态改为「已定版」。此后进入 dev 的提交一律归下一个版本。
4. 更新任一版本文件后,同步本 README 底部的版本索引。
