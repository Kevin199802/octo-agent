# Method 05 用例

以下为输入与预期，均不代表执行通过；判定见[评价](../04-references/methods/05/evaluation.md)。

| 用例 | 输入 | 预期 |
| --- | --- | --- |
| 05-01 | 6模型比较TTFT、吞吐、成本、显存，方向不同，无评分公式，看优势短板与均衡 | 主05、平行坐标；保留原值/单位与方向；提供适用高亮、单指标排序和筛选；无等权或综合得分 |
| 05-02 | 延迟升高且吞吐下降，是否相关 | 04-2，不强套05 |
| 05-03 | 15模型只看谁TTFT最低 | 直接单指标排序，不强制平行坐标 |
| 05-04 | 40实验组×8指标，只比较重点几个 | 平行坐标结合Focus/筛选/分组；不靠40种颜色，不发明通用数量上限 |
| 05-05 | 6模型谁综合第一，只有原指标，无权重公式 | 说明评价模型缺失；可先视觉比较；不自行等权、归一化求和或报综合第一 |
| 05-06 | 明确想用雷达图比较6模型 | 可实现指定方案，保持数据语义；不回写默认方法，不用面积排名 |
| 05-07 | 缺平行坐标专项，先做HTML | 按明确载体交付；沿用通用规则，未定义样式标当前建议，不因缺专项换图 |
| 05-08 | TTFT为ms、吞吐为tokens/s、成本为$、显存为GB，无统一评分尺度 | 独立轴保留原单位；轴到像素不等于业务分数；不创建0–1综合表现值 |
| 05-09 | 已知多模型多指标，想看均衡与短板 | 保持平行坐标，轮廓仅作相对位置阅读，不因“均衡”主动改雷达 |
| 05-10 | 只要准确原值与逐列排序，不关心轮廓 | 表格可为主，说明任务适配 |

原始05-01还需检查：专项规范缺失不阻止生成，未定义参数不冒充正式规则；不自动Min-Max/Z-score作为业务评价，也不引入无依据的固定数量阈值。其他语义边界统一按[数据语义](../04-references/data-semantics.md)。
