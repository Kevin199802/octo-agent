# 图表设计公共入口规则

这是独立调用与嵌入下游共用的规则正文，不含Skill注册元数据，不要求宿主将其注册为独立Skill。嵌入时由宿主入口承接或按需读取本页，具体入口文件名和调用方式由宿主决定；遵从用户要求及承载工程的真实协议，不指定下游目录层级。

输出可执行的图表方案；需要原型时，预览与交付使用同一份图表实现。

## 核心规则

- 按用户目标选择方法和载体，再应用适用规范。已有定义沿用；未定义部分作为本次设计建议，不因规范缺口停止生成或换图。实际冲突先核对适用范围，再说明取舍，不假称全部合规。
- Method 05 在任务适配时首选平行坐标；用户指定其他载体或实际不适配时按任务调整，不将个案改成默认方法。
- 保留原值、单位、时间、对象身份及缺失语义；不自行建立业务评分、权重、阈值或已确认根因。案例参数只在其来源场景适用。
- 用户指定领域优先；领域不明用中性、明确标记的示例数据，不从方法案例推断行业。内部组件/API 未提供时不声称已接入。

## 原型交付硬门槛

- 先判定交付格式：用户明确指定技术栈或单文件时遵从；否则优先接入既有Vue工程并遵从其目录、依赖、编译门禁、预览和导出机制；没有承载工程时交付完整 Vue 3 + TypeScript + ECharts + Vite 工程。`index.html` 只是工程入口，单独一个 `.html` 文件不能作为默认路径的完成产物。历史参考 HTML 不能改变此判定。
- 对“半导体四箱体、640→420px、散点/密度短线、截图窗口”这一匹配案例，可从[四箱体工程骨架](../04-assets/semiconductor-four-box-vue/)复制并替换示例数据、文案和规范映射；其他任务不要直接套用这个案例。
- 既有工程不整体复制骨架或覆盖宿主配置；原型交付前执行[产物门槛](../03-references/prototype/delivery-gates.md)。结构检查、测试/构建、目标尺寸浏览器检查及实际导出分别记录。失败先修复；无法运行的项目标记“未验证”，不能写成“代码完整稳定”或“视觉符合规范”。

## 工作流程

1. 确定分析目标、对象/指标、数据与输出媒介；仅缺少关键业务信息时澄清。单指标排序、明确图表请求和规范咨询可直接处理。
2. 需要方法匹配时读取[路由表](../01-router/route-map.md)，选一个主方法，必要时最多两个辅助方法；状态以[方法索引](../02-methods/index.md)为准。读取选中的短卡及其按需引用；待实现方法按路由表回退。相邻任务难区分再读[路由详解](../01-router/method-router.md)，旧编号请求读[编号迁移](../01-router/id-migration.md)。
3. 按下表加载实现所需资料，完成方案或原型。使用ECharts时先核对所需能力；无法实现或需要其他技术配合的部分，按能力边界规则主动告知用户。只检查本次需要及已承诺的能力，分别记录实际验证与未验证部分。
4. 先说明“要判断什么 → 推荐方案 → 关键交互”；有原型则交付文件，简述示例数据、处理口径和适用边界。内部路由、规范清单不默认放进产品界面。
