# 图表规范编写规则

仅在新增或整理规范时读取。规范用于约束图表表达，不替代方法选择，也不因局部规则缺失阻止方案和原型生成。

## 正文内容

- 开头说明适用图表、领域和必要例外。
- 按实际内容组织数据要求、视觉参数、交互、响应式和使用边界，不为补齐栏目添加空内容。
- 参数直接写入表格或条文；更新后保留一份当前规则，不用“已确认”“来源值”“见下节新增规则”等过程描述替代具体要求。
- 公共规则引用唯一正文；专项直接写本类型的差异，不重复维护另一套公共数值。
- 正文不添加来源沿革、文档覆盖状态、修订过程、验证历史或逐条规则级别标签；来源、日期和变更依据保存在本地维护记录中。

## 规则与边界

明确区分必须要求、默认方式、可选能力和实现建议，直接说明生效条件；不能因删除状态标签而把建议变成强制要求，或把有条件的参数变成全局规则。

已有规则适用就使用；未定义项写清具体范围，按任务说明设计选择。真实冲突按当前适用入口的规则与优先级处理，不静默假称合规。未定义项不自动跨领域继承，单次参数不升级为通用阈值，未知组件接口不虚构为已接入能力。

## 更新与维护

新增领域规范时在[规范索引](index.md)登记选择条件和按需入口；设计规则、内部技术契约与缺失依赖分别处理，不复制整个Skill。

更新参数或行为后，同步检查入口、专项、方法详解及验收预期的引用、锚点和“未定义/尚未覆盖/默认”等描述。补齐的缺口引用当前规则，合法的局部缺口和历史事实继续保留。

规范正文说明要求，具体工程的HANDOFF记录实际采用及验证情况；静态内容整理不能替代运行、视觉、交互或业务集成验证。
