# Chart Spec Schema

仅在整理/新增规范时读取。图表规范补充选定设计的已有定义，缺口不阻止推荐和原型生成。

新增领域规范先在[规范索引](index.md)登记选择条件和按需入口；视觉值仅在所属规范维护，技术契约与缺失依赖分开记录，不复制整个Skill。未定义项不自动跨领域继承。

## 建议结构

状态与来源、定义、适用/不适用条件、数据要求、组成、视觉、颜色、轴、图例、Tooltip、交互、响应式、密度、状态、Do/Don't、原型说明、缺口、验证记录与变更。

## 覆盖与验证状态

DRAFT表示内容待核对；PARTIAL表示已接入部分规则；VALIDATED须附来源、版本/日期和已核对范围，仅指该规范内容的核对，不等于图表运行或业务集成通过。状态与规则强度分别记录，不能因标记VALIDATED将所有建议变成硬规则。

## 规则级别

| 级别 | 含义 |
| --- | --- |
| HARD RULE | 来源明确要求；写清适用范围，适用时沿用 |
| RECOMMENDATION | 来源给出的默认/推荐方式，可按业务调整 |
| CONTEXTUAL | 仅在具体条件下成立，条件与例外同时记录 |
| SOURCE-DEFINED / LEVEL-PENDING | 有来源记录，正式级别尚未明确 |
| CURRENT PROPOSAL | 本次方案建议，可用于完成原型，不宣称内部事实 |

已有规则适用就使用；未定义部分依据方法实现。真实冲突按 SKILL.md 处理，不静默假称合规，也不把缺规范变成阻塞。

不把能力存在等同于推荐，不把单次参数升级成通用阈值。通用分类色板适用范围按用户本轮确认执行；不从其数值编造 Token API。

按实际规则选用栏目，不为补齐模板虚构来源、参数或验证结果。修改规范时记录来源、日期、适用范围与维护人；文档整理不能把历史能力描述升级为运行验证通过。

新增或更新定义时，同时检索引用它的入口、专项、方法详解和验收预期中的“未定义/尚未覆盖/默认”声明。按领域、媒介、对象和历史时点判断，已被补齐的缺口改为引用权威正文；合法的局部缺口和历史事实保留。只更新正文或链接存在不代表描述已同步。
