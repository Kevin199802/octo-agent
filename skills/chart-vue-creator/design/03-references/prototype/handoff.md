# 原型工程交接说明

生成或更新图表原型工程时，随本次页面/组件交付与代码一致的 `HANDOFF.md`。新建独立工程默认放在根目录并从README链接；既有工程按承载环境放在允许的交付目录，不覆盖原有HANDOFF或强制修改README。最终交付说明必须给出文档入口。适用于 Vue/ECharts 和用户指定的其他技术栈。纯设计咨询、单张静态图或仅要求单文件 HTML 时不强制增加独立文档；用户明确要求交接说明时提供。

## 内容要求

按实际案例填写以下内容；简单工程可合并章节，不填空模板，不复制整套 Skill 规范。已有 README 的安装步骤直接引用，避免维护两份命令。验证项目与结果判定按[产物门槛](delivery-gates.md#结果与完成条件)，既有工程的门禁入口与日志按[承载规则](hosted-project.md)记录。

| 内容 | 应说明什么 |
| --- | --- |
| 任务与交付范围 | 用户需要完成的分析判断、实现的图表与功能、演示数据还是实际输入 |
| 规范来源 | 实际采用HD、半导体或用户指定规范及选择依据；记录来源版本（未知则注明）、Skill版本、案例覆盖、临时补充及未接入的内部组件/Token/runtime，不以Skill版本代替标准版本 |
| 设计约定 | 本案例确认的关键视觉参数、数据口径和交互行为；区分平台/领域已有规范、用户确认的案例要求与本次建议，不把案例值提升为全局规则 |
| 工程结构 | 实际文件路径及职责：图表、数据处理、演示页、窗口/控件；明确可复用部分、演示专用部分和尚未拆分部分 |
| 能力与接入 | 真实的数据类型、props/事件/方法或其他栈对应接口；依赖与版本文件；容器尺寸响应、样式配置、导出等必要能力，以及业务组件替换位置 |
| 使用示例 | 给出使用本工程真实组件和接口的最小示例，可引用随包可运行文件；业务组件未知时另列待映射事项，不写虚构包名/API为可运行接入代码 |
| 验证与限制 | 分别记录编译/构建、视觉交互、导出、业务接入的实际结果及未执行项，附必要命令、入口和对应最终代码的证据路径；说明失败、功能缺口和内部验证项。设计确认与工程接入分开，不由编译结果推定其他检查通过 |

有截图编辑功能时，说明窗口交互和图表绘制各由哪个文件负责，以及快照数据/状态是否独立、原貌和重置各改变什么、导出包含什么。若代码仍共用数据或把交互写在演示页，准确记录当前结构和所需调整，不能把建议的分层写成已完成。

## 内部组件与保密资料

不以提供内部源码为交接前提。内部组件不可访问时，记录通用实现已具备的能力、业务组件需支持的操作，以及由内部开发完成的映射和验收。只有工程实际提供了可替换入口或连接层，才称为“可替换”；否则明确标为待实现。

按本次任务列能力表，可使用“当前实现 / 业务组件需提供 / 接入后检查”三列。例如密度短线属于图表绘制，浮窗拖动属于界面交互；该区分不证明内部组件已有相应能力。对业务组件不支持能力的处理建议需标为建议，不静默绕过业务规范。

交付状态用明确描述：仅设计建议、通用工程可运行、业务组件适配待验证、已在指定项目验证。只有目标项目中的实际证据支持最后一种；文档完整或本地构建通过不等于业务可直接上线。

ECharts的限制、补充技术与告知内容按[能力核对](echarts-capabilities.md)写入本文档。

## 交付前核对

1. 文件路径、接口名、参数默认值、交互语义与当前代码一致；示例调用已存在的接口，依赖说明与工程版本文件一致。
2. 用户明确要求和已承诺能力有对应实现或已说明缺口；验证结论符合[产物门槛](delivery-gates.md#结果与完成条件)。
3. 约定位置有本次 `HANDOFF.md`，最终交付入口有效；新建独立工程的README入口有效。实际导出的代码包包含该文档和引用的必要文件；工程原有HANDOFF不能代替本次设计交接。
4. 后续修改设计或实现时同步更新交接说明。文档不替代实现；代码尚未具备的能力不通过文案补齐。
