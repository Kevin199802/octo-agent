# 原型生成与验收要点

生成或修改图表原型时读取，包括仅调整样式、数据更新或交互；局部修改只读取受影响元素的适用规范，检查本次改动及直接受影响的已有行为，不扩大功能范围。正式视觉数值由[所选规范](../chart-spec/index.md)维护。

## 业务与参考代码

- 用户明确的领域、对象、指标优先于方法卡案例。ICT运维不能因采用03就生成光刻机/良率数据；没有领域时可用设备A/B等中性名称与明确标注的示例指标，不暗定行业或真实告警阈值。
- 复用参考代码前区分业务数据、图形/交互逻辑、视觉样式。保留适用逻辑，替换不符任务的数据；公共字体、文字层级、图例、布局按当前适用规范重新配置。源HTML原样保存用于溯源，不代表其所有旧样式继续适用。
- Mini所需专项尚未覆盖的部分沿用适用公共规则；HD已有Mini信息压缩建议见[布局](../chart-spec/common/layout.md)，其他未定义处按本次设计处理；不能把旧Demo或临时像素值称为正式规范。用户明确忠实复现时说明与公共规则的差异。

## 公共规范落地

实现前将实际用到的元素对应到所选规范定义，实现后在目标尺寸核对；内部记录规范来源、实现位置及检查结果，交接仅保留必要结论、偏离和证据位置：

| 元素 | 核对内容 |
| --- | --- |
| 文字 | 字体与已定义角色字号/行高；SVG/Canvas也需预留对应行框，不能仅替换font-family |
| 轴相关文字 | 分清轴标题、刻度标签、单位，读取已有定义；无定义的轴标题规则作为设计建议，不套用单位位置冒充规范 |
| 图例 | 已定义标记形态/尺寸、文字、项内及项间间距、可选位置；按公共默认或明确适用的专项例外执行（如饼图右侧居中）；不得仅因示例采用右侧竖排或缩字就照搬 |
| 布局与操作 | 对实际相邻区域核对布局文件的间距、图标和分隔线规则；不存在的区域不机械累加留白 |
| 色彩与状态 | 分类身份稳定，沿用适用色板；业务阈值和状态有来源或明确为模拟 |

具体数值从所选规范的对应文件读取；HD视觉值读取common目录；跨领域Tooltip读取common/tooltip.md，避免在本文件维护另一份数值表。现有组件、自绘和复用Demo均需核对；真实尺寸冲突可说明取舍，不能笼统宣称全部符合。

### ECharts 规范到实现的对应

本表是公共元素实现映射的唯一维护位置，适用于Vue、单文件HTML及业务封装使用ECharts的任务，不改变入口选定的交付格式。其他引擎沿用上面的规范核对要求。表内不是全部必需元素，只对本次实际出现或受影响的元素使用。

属性已按内置工程锁文件的ECharts 5.6.0核对；目标工程仍须依据其锁文件/实际加载版本及真实组件接口核实，不因同用ECharts就认定接口一致。规范数值继续从所选规范读取，不在此复制。

| 元素 | 实际控制位置与边界 |
| --- | --- |
| 外层标题、说明、操作文字 | 对应DOM/CSS；图内标题用`title.textStyle`、`title.subtextStyle`，外层CSS不能替代图内配置 |
| 坐标轴刻度 | 对应轴的`axisLabel`（如`fontFamily`、`fontSize`、`lineHeight`、`color`）；核对具体轴及富文本局部样式 |
| 轴标题、单位 | 图内轴名称用`name`、`nameTextStyle`、`nameGap`等；独立单位文字按其实际DOM或绘制配置处理，不混用刻度、轴标题与单位角色 |
| 图例文字、标记 | 内置图例用`legend.textStyle`、`icon`、`itemWidth`、`itemHeight`；自绘或业务图例核对真实实现 |
| 图例间距、位置 | `legend.itemGap`是项间距，不是标记与文字间距；定位核对`left/right/top/bottom`等实际配置。5.6.0内置图例的标记与文字偏移在绘制源码中固定，不能伪造一个配置项或用`itemGap`冒充项内间距；无法直接满足规范时按能力边界说明，并核对可用的业务接口或自绘实现及其交互 |
| 图形身份色 | 按真实系列/数据项及图形类型核对`itemStyle.color`、`lineStyle.color`等；以稳定对象ID保存分类身份映射，不能仅传ID就认定引擎会保持颜色，也不能按排序后的下标重新分色 |
| 区域布局间距 | 外层布局由CSS控制；笛卡尔绘图区由`grid`等配置控制。`grid.containLabel`涉及刻度标签的空间，不等于替标题、图例等所有区域预留空间；容器边距、绘图区边界与实际元素间距分别核对 |

已知业务封装优先用其真实接口；接口未知时记录待映射项，不虚构属性。规范明确的参数应显式落实，或核实组件默认确实符合要求。后续主题、响应式配置和更新不得无意覆盖仍适用的规范；用户明确覆盖和规范规定的合法状态变化按既有优先级执行。

分类身份色在排序、筛选和分页后保持映射；隐藏、聚焦等显示态遵从适用规则，恢复后还原身份色。状态色、连续数值色按真实业务/数值语义检查，不要求像素颜色始终不变。

API核对来源为Apache ECharts 5.6.0的[标题](https://github.com/apache/echarts/blob/5.6.0/src/component/title/install.ts)、[轴类型](https://github.com/apache/echarts/blob/5.6.0/src/coord/axisCommonTypes.ts)及[文本/系列类型](https://github.com/apache/echarts/blob/5.6.0/src/util/types.ts)、[图例配置](https://github.com/apache/echarts/blob/5.6.0/src/component/legend/LegendModel.ts)与[图例绘制](https://github.com/apache/echarts/blob/5.6.0/src/component/legend/LegendView.ts)、[绘图区](https://github.com/apache/echarts/blob/5.6.0/src/coord/cartesian/GridModel.ts)。这些是实现依据，不替代目标工程生效检查。

## 安全区隐藏的实现核对

仅使用[过滤正常范围](../methods/01/detail.md#过滤正常范围)时读取本节。现有属性表的5.6.0核对不代表已验证区间折叠能力；先按目标依赖及业务封装核实可用实现，不虚构跨版本配置属性。

先按01规则判定是否需要折叠；无异常时走完整线性轴路径，清除旧折叠带和展开入口。实际折叠时，上方开关及Y轴展开入口与图表共享同一过滤状态。轴边界、刻度、曲线裁剪、命中测试和Tooltip须使用一致的当前坐标映射；双阈值须同时保留上下两侧，不能以只保留一段的普通缩放或删除正常记录冒充中间区间隐藏。目标能力不足时按[能力边界](echarts-capabilities.md)说明自定义绘制、界面层或业务组件需提供的配合；替代方案改变分析含义时先取得用户选择。

缩放、容器resize、数据/阈值更新后重算展开入口位置，不能用固定像素定位。导出若不包含外层DOM，需按实际导出路径保留折叠说明与阈值；分别验证全部正常不折叠、缺失独立统计、共享Limit适用条件、异常点状态与系列线色分离、开关/展开联动、双侧数据、跨界线段、投影标记原值追溯及恢复，不以配置存在或构建成功替代。

## 尺寸语义

输出宽度、当前宿主宽度、图形优化断点分别解释。用户“做420px宽报告图”只规定输出尺寸，不等于“W≤420才优化”；明确“断点420px”才作为阈值覆盖。半导体配置及原貌行为按[响应式专项](../methods/03/semiconductor-responsive.md)，普通Mini不继承其断点。

## 悬浮提示

桌面Hover读取[通用Tooltip组件](../chart-spec/common/tooltip.md)：四种布局、视觉/触发/定位、移入长卡片滚动及隐藏清理以该文件为准，避免重复规则。普通只读提示与可滚动卡片分开处理，不能对全部卡片统一设置不接收指针事件或离开目标立即销毁。固定选择Pin与临时提示分开；静态截图必要信息用标签/附表保留。

## 任务范围与证据

实现前在内部明确本次需要哪些交互及可观察结果。按用户目标判断原貌、尺寸调节、样式调节和导出是否需要，不因Method03自动加入全套编辑器。仅要求420px原貌切换时，不把未要求的拖动调节当作遗漏；用户要求可编辑截图工具时才落实对应控件。图片导出须确认文件实际产生、可打开且内容符合约定，不能将打开快照窗口称为下载。

检查用户明确要求、方案已承诺、界面已呈现的交互：实际触发→观察变化→必要时恢复。对本次已存在或已承诺的更新、排序、筛选、分页和隐藏操作，在操作后复查相关规范，不为检查新增产品功能。

DOM元素检查计算样式；图内元素核对当前实例对应的生效配置与绘制结果，Canvas容器的CSS不能证明图内文字样式。实例配置（如`getOption()`）只能证明配置状态；字体实际回退、富文本局部样式、交互状态及实际几何布局仍需结合实现与渲染结果核对，不能仅因配置符合就判最终视觉通过。在目标图表容器尺寸检查重叠、裁切和布局，不以浏览器视口宽度代替容器尺寸；截图不能单独证明精确字号、色值或间距，源码、初始配置和构建成功也不能单独证明最终生效。

区分静态配置检查、实际运行和视觉交互证据；结果及未验证项按[产物门槛](delivery-gates.md#结果与完成条件)记录。方法专项的PARTIAL是方案质量结论，不代替执行状态；无需设计师先审批检查清单。

## 输出前核对

只核对本次实际使用或受影响的内容，无需向用户展开内部清单：

- 任务、领域、数据与媒介一致，示例数据有标记；原值、单位、时间、业务方向、缺失和变换按[数据语义](../data-semantics.md)，不自造评分、权重、阈值或根因。
- 按上文检查身份色、目标尺寸和状态。跨对象比较保持参照口径，有意重算范围须有明确操作及说明；静态图直接保留判断必需的信息。
- 交互有可观察结果，按任务支持恢复；无数据、失败与筛选无结果可区分。核心操作键盘可达、焦点可见，必要时提供触屏替代；颜色不是唯一线索。
- 图形与文字可辨，低对比或重叠时调整；文件可打开、外部资源可用。未运行的行为或无障碍认证不得声称通过。
