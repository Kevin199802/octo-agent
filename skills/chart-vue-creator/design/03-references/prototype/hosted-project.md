# 既有工程与管道接入

实现前识别承载环境。已有工程/管道时遵从其声明的工程路径、可写目录、允许修改的入口、现有依赖和版本、验证入口、预览入口与导出入口；从项目说明或工具结果读取，不猜测路径、命令或成功状态。没有承载工程时沿用独立Vite默认路径。用户明确指定交付方式优先。

## 写入与依赖

- 在允许的页面目录写组件、数据处理、样式和本次HANDOFF；只修改明确允许的挂载入口。不得为了满足独立工程检查覆盖根目录README、HANDOFF、package.json、锁文件、应用壳或构建配置。
- 遵从承载工程认可的UI组件库和ECharts导入方式。例如环境要求全量引入时，不照搬骨架的echarts/core按需注册。复用骨架只取适用逻辑与组件，调整相对路径、接口及规范映射，不整体复制配置或测试依赖。
- 已有且有接口说明的业务图表组件优先复用；只有ECharts或接口未知时如实记录直接实现与接入缺口。在业务脚手架编译成功不等于已经复用业务BoxPlot组件。
- 管道控制依赖安装时使用指定入口，不自行npm ci、替换包管理器或引入另一棵依赖树。环境资料不足时完成可确定的代码工作并说明缺失项，不伪造内网资产。

## 验证、预览与导出

- 使用指定验证门禁，不另起构建/服务进程替代门禁，不修改管道脚本绕过失败。代码错误修复后重跑；环境失败按环境支持方式处理并如实说明。必须门禁失败或未执行时不能称交付完成。
- 结果必须对应本次最终代码；记录门禁输出与可用日志/运行标识。webpack开发编译、独立类型检查、生产构建是不同检查，不能互相推定。无输出证据即未验证。
- 使用宿主规定的预览入口及展示格式；更新后按宿主要求重新给出入口。预览地址生成不代表图形和交互正确；能检查时实际检查，无浏览器能力时标记未验证，可记录设计师明确反馈及其范围。
- 用户需要代码包时，通过管道指定的导出入口生成，不自行压缩含共享依赖链接的工程目录。导出包必须对应最终代码，包含本次HANDOFF及必要文件；打包成功不代表编译通过，导出前确认最新门禁结果。
- 完整工程由脚手架与本次页面共同组成，无须另建第二个Vite工程。安装/启动命令遵从工程实际脚本；若目标为yarn install和yarn serve，记录其要求及验证情况。共享依赖池预览通过不等于导出包在干净环境已安装启动成功；未经实测不宣称“拿到就能跑”。

环境约定只决定工程执行方式，不免除数据语义、设计规范、能力告知或实际证据要求。无需把某一管道的固定路径、协议或安装脚本写成所有环境的通用规则。
