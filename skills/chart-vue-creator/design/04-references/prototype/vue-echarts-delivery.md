# Vue 3 / ECharts 可交付代码

适用于入口选定的Vue 3 + TypeScript + ECharts路径。设计师预览调用交付给开发的同一Vue组件；示例数据与窗口工具通过清晰接口使用该组件，设计修改直接落在这份实现中。

## 交付边界

- 先按[承载工程规则](hosted-project.md)判定新建还是接入既有工程。既有工程沿用其依赖和构建方式，在允许目录交付组件；无承载工程时提供可运行的 Vite + Vue 3 + TypeScript 演示工程。交付真实组件接口、依赖版本依据和接入说明，不为满足独立工程结构改动宿主配置。演示页面的业务文案、示例数据和窗口工具不写死进核心图表组件。
- 预览工程通过 props 向核心组件传入明确标记的示例数据。Vite 所需的 index.html 只是应用入口，图表方案以 `.vue` 组件及其数据处理文件为准；设计修改直接落在这份组件实现中。
- 用明确的输入类型说明对象 ID、指标、单位、数值、缺失值、颜色身份及业务阈值来源；示例数据与真实数据分开。数据变换保留可解释口径，不擅自引入评分、权重或阈值。
- 将数据整理、ECharts option 构造、Vue 生命周期和演示交互分开。组件应随容器变化重算与 resize，卸载时释放实例和监听器。常规图表可用 dataset，特殊几何可用 custom series。
- 对下游项目提供输入 props 与必要事件；没有真实接口时提供适配点和示例，不把模拟数据写成后端契约。内部 Token、Chart+、D2C 或 API 未提供时明确列为待接入项。

## 交付前检查

1. 按[产物门槛](delivery-gates.md)使用当前承载方式对应的验证入口：既有工程遵从指定门禁；新建默认Vite工程仅在环境已确认有可用Python解释器时使用 `scripts/check_prototype.py <工程目录> --run`。Python不可用或状态不明时，不安装或试运行系统Python探测；改为直接核对产物门槛中的工程结构，并通过项目已有的Node/包管理器执行test、build。结构判定沿用产物门槛：缺少必需文件、依赖声明或test/build脚本记FAIL；结构符合但执行环境不可用时，对应执行项才记未验证。分别记录结构检查的方式与结果、Python脚本未执行、测试/构建实际结果及其他未执行项；不把脚本未执行写成测试或构建未执行，也不能替代浏览器视觉检查。
2. 按[生成与验收](generation-review.md)在目标尺寸检查图形、状态及承诺交互。
3. 为复杂图形加入能捕捉真实失败的检查。例如箱图的点云与箱体同分类中心、jitter 与箱宽的关系、密度短线宽度和模式切换；这些案例规则只适用于相应方案。
4. 将“设计确认”和“工程集成”分开记录：前者确认分析任务与视觉方案，后者确认组件接口、业务数据映射、内部规范适配和目标项目构建。

缺少某项运行条件时，如实标注未验证项；不能因为静态源码存在就宣称可直接上线。

## 能力与交接

实现前按[ECharts能力边界](echarts-capabilities.md)核对需求并告知限制。工程随附[HANDOFF.md](handoff.md)，记录本案例的设计约定、真实接口、能力分工、接入示例及验证边界；最终交付提供入口；README及文档位置遵从Handoff规则。
